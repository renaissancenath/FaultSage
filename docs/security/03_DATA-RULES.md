# 03 Data Rules

## 1. Data inventory

| Data | Source | Stored where | Contains | Retention |
|---|---|---|---|---|
| Config | User | `.faultsage/config.toml` | Signal settings, paths | Until purge --all |
| Spool events | Collectors | `.faultsage/spool/` | Redacted event bodies | Deleted after ingest |
| Events | Daemon | SQLite `events` | Redacted event bodies | 30 days default |
| Incidents, hypotheses, evidence | Analysis | SQLite | File paths, lines, short redacted excerpts | Until purge |
| Checkpoints | Helper | SQLite `checkpoints` | Step name, type, shape, column names and dtypes | Until purge |
| Graph snapshots | Analysis | SQLite | Module and step names, edges | Replaced on rebuild |
| Backups | Apply gate | `.faultsage/backups/` | Copies of patched files before change | 30 days |
| Approvals | Apply gate | SQLite `approvals` | Who/how/when, patch hash | Until purge --all |
| Session | Daemon | Memory + `.faultsage/session` | One-time token | Until used or daemon stop |
| Self-monitoring | FaultSage | `~/.faultsage/self/` | FaultSage's own redacted errors | 30 days |
| Benchmark runs | Bench | FaultSage repo `results/runs/` | Case ids, predictions, metrics | Permanent (public) |
| Benchmark checkouts | Bench | FaultSage repo `data/` (gitignored) | Third-party code | Deleted with `bench clean` |

## 2. Never stored

- Values of environment variables, `.env` files, secrets, tokens, passwords.
- DataFrame or array contents, rows, sample values.
- Full source files or full log files.
- Personal data beyond what appears in git author names on commits already in the user's repo (we store commit ids, not author names).

## 3. Redaction (`faultsage.redact`)

Applied to every text field before storage, display or export:
- Known token formats (AWS access keys, GitHub tokens, Slack tokens, JWTs, private key blocks, bearer tokens).
- `key=value` and `"key": "value"` pairs where the key matches `pass|pwd|secret|token|api[_-]?key|auth|credential|cookie|session`.
- Values of environment variables present at collection time whose names match the same pattern (matched by value, never stored).
- High-entropy strings of 32+ characters in assignment position.
- Redaction replaces with `[redacted:<kind>]`. Regexes are linear-time (no nested quantifiers) and inputs are length-capped to avoid ReDoS.

## 4. Access

- Only the user who runs FaultSage. Data lives in the project folder and the user's home.
- The dashboard serves data only to authenticated local sessions (02_LOGIN-RULES.md).
- No telemetry, no analytics, no crash upload. Self-monitoring stays local. Optional GlitchTip forwarding only if the user configures their own self-hosted instance.

## 5. Export and sharing

- Exports (Markdown, JSON) contain only redacted data and are written where the user chooses.
- Export header states: generated by FaultSage version, time, and that content is redacted.

## 6. Deletion

- `faultsage purge`: events, incidents, backups, spool.
- `faultsage purge --all`: the whole `.faultsage/` folder.
- `pip uninstall faultsage` leaves project data; README tells users to purge first if they want it gone.

## 7. Benchmark data

- Licences of each dataset recorded in `data/LICENSES.md` before use.
- Third-party code is not committed. Only case ids, our predictions and metrics are published.
- Published per-case outputs contain file paths and function names from public open-source repositories only.
